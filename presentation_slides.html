Problem Understanding & Solution Design

Rubric: Problem Understanding (8 Marks)
Challenges in Traditional Real Estate
  • Fragmented Channels: Communication between tenants, managers, and property owners occurs via unstructured calls/texts with no verifiable record.
  • Unverified Property Listings: Bogus listings and outdated price information without administrative validation.
  • Manual Tenancy Agreements: Paperwork delays, lack of status tracking for rent deposits and lease contracts.
  • Absence of Auditability: Lack of real-time monitoring and activity logs for security and compliance.
Proposed EstateHub Solution
  • Dedicated 3-Role Portals: Distinct workflows for Administrator, Property Manager, and Tenant.
  • Administrative Quality Control: Pre-publication approval/rejection pipeline for all property submissions.
  • Digital Rental Pipeline: Online rental applications, automated acceptance/rejection feedback, and formal lease issuance.
  • Direct Communication Hub: Built-in messaging between verified tenants and property managers.
System Vision: Deliver a centralized web application balancing intuitive consumer UI with secure, auditable role-based administration.

Relational Database Design & Schema

Rubric: Database Design (8 Marks)

Normalized schema (3NF) designed with relational integrity, foreign key constraints, and indexing for optimal query execution.

USERS
  • PK id (BIGINT)
  • email (VARCHAR, Unique)
  • password (VARCHAR)
  • role (VARCHAR)
  • name, phone, bio
  • rental_history_notes
PROPERTIES
  • PK id (BIGINT)
  • FK manager_id → Users
  • title, address, city, state
  • price, security_deposit
  • bedrooms, bathrooms, sqft
  • status (PENDING/APPROVED)
APPLICATIONS
  • PK id (BIGINT)
  • FK property_id
  • FK tenant_id
  • move_in_date (DATE)
  • monthly_income, occupation
  • status (PENDING/APPROVED)
AGREEMENTS
  • PK id (BIGINT)
  • FK property_id, tenant_id
  • FK manager_id
  • start_date, end_date
  • monthly_rent, deposit
  • status (ACTIVE/TERMINATED)
Supporting Relational Entities: MESSAGES (1-on-1 tenant-manager chat threads), ACTIVITY_LOGS (real-time timestamped audit events), SYSTEM_SETTINGS (key-value platform configurations), and NOTIFICATIONS (tenant/manager alert notifications).

Multithreading & Concurrency Control

Rubric: Multithreading & Synchronization (4 Marks)
SystemMetricsTracker & Worker Pool

To handle concurrent web requests safely without race conditions or data inconsistency, a dedicated concurrency module was implemented:

  • Atomic Variables: AtomicLong and AtomicInteger provide lock-free, thread-safe counter increments for live page requests and search inquiries.
  • Synchronization: synchronized methods and dedicated mutex monitor locks guarantee atomicity when resetting system metrics.
  • ThreadPoolExecutor: Dedicated background worker pool executes asynchronous audit logging and notification tasks without blocking the main web request thread.
